The Problem

Every deploy is a 6-step manual ritual

Developers must manually update image tags in gitops-argocd-non-prod_15255 before ArgoCD can deploy.

Clone the GitOps repo locally
Branch Create a new branch from master
Locate Find the correct *-dc.yaml Kustomize patch file
Edit Update the value: line with the new container image tag
Commit + PR Respect the Jira-enforced commit regex, push, raise PR on GitHub
Wait for review & merge A second team member must approve — then manually merge

Our Solution

Design Consideration

Built to respect existing GitHub rulesets

Handled — CHG1039315

Enterprise default branch security (force push block, delete restriction). Pipeline uses squash merge — fully compliant.

Handled — Copilot PRReview

Targets 100+ branches. Pipeline polls with 30 retries × 10s = 5 min max to allow Copilot review before merge.

Future-Proofed — Jira Commit Rule

Currently disabled but targets all branches. Commit message pre-formatted as [TICKET-123] chore: promote svc tag — compliant when re-enabled.

No Impact — File Path Restriction

Enterprise ruleset restricts agents/*.md. Pipeline only edits *-dc.yaml — zero conflict.

What We Built

Key tasks & deliverables

📝ADO Pipeline Template

Reusable YAML template using extends: — one template covers all services & environments

🔍dc.yaml Auto-Discovery

Script recursively finds the correct Kustomize patch using service name + environment — no hardcoded paths

🔑Scoped Service Account

Pipeline authenticates via a dedicated GitHub PAT in ADO variable group — zero developer write-access required

⏱️Mergeability Poller

Retry loop (30 × 10s) waits for GitHub rulesets & Copilot review to pass before auto-merging via REST API

🏷️Structured Commit Messages

Auto-generated as [TICKET-NNN] chore: promote {svc} {tag} — Jira ruleset-compliant by default

🛡️Conflict Resolution

Detects existing open PR for same branch, closes it before creating a fresh one — prevents duplicates on re-runs
